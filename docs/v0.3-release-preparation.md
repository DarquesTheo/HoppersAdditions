## Build and artifact verification

Use the full compatible JDK documented in README, not the default JDK 25:

~~~powershell
$env:JAVA_HOME = "$env:USERPROFILE\.jdks\corretto-23.0.2"
$env:PATH = "$env:JAVA_HOME\bin;$env:PATH"
.\gradlew.bat -I tools/pulse-regression.gradle :common:clean :fabric:clean :neoforge:clean :common:build :fabric:build :neoforge:build :common:pulseRegression --console=plain
.\tools\release\Verify-ReleaseArtifacts.ps1
~~~

Ordinary Gradle test tasks have no test sources. The Pulse harness uses production
methods, real containers, and a fake level; it does not run a loader or world.
The package verifier checks expanded metadata, required feature classes/resources,
JSON and custom references, Java 21 bytecode, and distributable names. Its JSON
report records the current commit, dirty state, artifact sizes, and SHA-256 hashes
under ignored build/issue7-evidence/. Final committed-build results and hashes
belong in issue #7 so the evidence does not require a self-referential commit.

Only distribute these normal remapped JARs when the release gate is resolved:

- fabric/build/libs/hoppers-additions-fabric-0.3.jar
- neoforge/build/libs/hoppers-additions-neoforge-0.3.jar

Minecraft 1.21.1 only, Java 21 bytecode. Fabric requires Loader >=0.18.4,
Architectury >=13.0.8, and Fabric API (build pin 0.116.9+1.21.1).
NeoForge requires >=21.1.220 <21.2 and Architectury >=13.0.8. These metadata
ranges are not evidence that every permitted dependency combination was tested.
