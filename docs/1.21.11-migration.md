## Safety and acceptance

This is a feature-preserving compatibility release, not new mechanics. All
twelve hopper variants, identifiers, recipes, components and saved state must
remain covered. 1.21.11 is the active target; 1.21.1 releases are legacy, with no
parallel feature backports. Downgrading an upgraded world is not supported.

Compilation, isolated harnesses, packaged-JAR verification, loader startup,
gameplay and saved-world upgrades are separate gates. Never infer startup,
gameplay or save acceptance from a build. Never accept the EULA on behalf of
the maintainer. World testing must use disposable copies of backed-up 1.21.1
worlds, never the only copy of a real world.

## Port and save-format review

- Preserve the Architectury structure and twelve registry IDs. No new hopper,
  icon, balance or routing change. Explicit block/item resource keys and a new
  tooltip bridge adapt the target API without changing existing tooltip content.
  Pickaxe enchantability 10 is now expressed by the item component.
- Thirteen recipes use target string ingredients with unchanged patterns,
  counts and results. Twelve item definitions reference existing models.
  Existing textures, loot, tags and translations are retained.
- Value-based serialization preserves inventory/loot-table data, TransferCooldown,
  Splitting NextDown, Pickaxe BreakProgress/EfficiencyLevel/FortuneLevel,
  and Pulse state keys/defaults. Target callback signatures and runtime access
  rules are adapted for both loaders.
- Harness round trips and legacy-shaped tags are NOT a 1.21.1 world conversion.
  Mojang world/item data fixes and modded enchantments/components need an actual
  saved-world upgrade. No supplied 1.21.1 world was opened or upgraded.

## Packaged runtime reproduction

Use only normal JARs and separate runtime dependencies: Fabric API and
Architectury Fabric on Fabric; Architectury NeoForge on NeoForge. Never put both
loader artifacts in one instance. Artifact hashes are in the evidence receipt.

The helper downloads official Mojang/loader profiles and libraries and creates a
disposable build/issue8/client-<loader> instance with an offline smoke identity.
It does not edit EULA files or import existing worlds. This is not authenticated
multiplayer. Metadata SHA-1 checks are applied where supplied. Use an authenticated
launcher for full manual acceptance.

```powershell
./gradlew.bat :fabric:downloadAssets --console=plain
./tools/release/Start-PackagedClientSmoke.ps1 -Loader fabric
./tools/release/Start-PackagedClientSmoke.ps1 -Loader neoforge
```

Each helper launches java @client-args.txt and records PID, command and artifact
hash in receipt.json, with stdout.log/stderr.log. NeoForge uses the official
installer --installClient. Offline user-properties/Realms authentication errors
were observed; these do not prove authenticated multiplayer. Computer Use was
stopped by the user; no further UI automation or manual acceptance was inferred.

Dedicated-server attempts used Fabric's official 1.21.11/0.20.1/installer-1.1.2
server launcher and NeoForge 21.11.48's official installer --installServer:

```powershell
# In disposable build/issue8/runtime-fabric:
java -Xmx2G -jar fabric-server-launch.jar nogui
# In disposable build/issue8/runtime-neoforge:
./run.bat nogui
```

Both discovered hoppersadditions 0.4.0+mc1.21.11 and stopped for the EULA.
Both generated eula=false and were left unchanged. NeoForge also reports a
missing server thread at that boundary; its batch exit code is not a startup
pass. A maintainer who agrees to the EULA must rerun, verify Ready/Done, connect
a matching client, then stop/save normally. Dedicated-server world loading,
automation and client-only dependency safety are NOT certified.

## Maintainer release checklist (both loaders)

All entries remain unchecked. Record loader, exact normal-JAR SHA-256, commands,
logs and before/after counts; distinguish assistant-observed and maintainer-
reported results. A harness pass does not check a live acceptance box.

- [ ] Reach client title UI and join a world on each final packaged loader;
  verify models/textures/tooltips, recipes, placement/facing, inventory UI,
  break/drop behavior and absence of missing mappings/resource errors.
- [ ] Reach dedicated-server Ready/Done, join with a matching client, verify
  inventory synchronization and no client-only server dependency errors.
- [ ] Exercise Reinforced, Pickaxe, Dropping, Magnetic, Filter, Monster, Animal,
  Batch, Small Batch, Splitting, Overflow and Pulse against legacy behavior.
- [ ] Check applicable redstone/comparators, sided inventories, hopper chains,
  minecarts and entities. Count items/entities across input/output/world; require
  no duplication/loss. Verify original speeds and stack limits.
- [ ] Pickaxe: enchantments, break progress, fortune/efficiency, placement/drops.
  Magnetic/Dropping: range/output/blocked cases. Monster/Animal: entity categories,
  drops/conservation. Batch/Small Batch: thresholds, partial/full outputs,
  stack limits and conversions.
- [ ] Filter: prototype slot, component-exact matching, named/enchanted/custom
  component stacks and save/reload.
- [ ] Splitting: front first; advance only after successful output. Missing/full/
  rejecting scheduled output waits instead of using the other branch. Check
  cooldown, redstone, chunk unload and saved next branch/inventory.
- [ ] Overflow: front priority per attempt; down only on front failure; both
  blocked wait. Include sided rejection and component-bearing items.
- [ ] Pulse: exactly one item per rising edge, none on held power/duplicate
  callbacks. Empty/failed pulses consumed, never replayed. Collection only
  unpowered; check input cooldown, collision collection, reload baselines,
  same-tick guards and external transfers.
- [ ] Repeat custom-state/inventory checks after chunk unload and complete
  stop/save/restart; compare components/counts, not just visuals.
- [ ] Back up a representative 1.21.1 world outside test instances and record
  legacy mod/loader versions/hashes. Make a separate disposable copy per loader.
  Upgrade each once; inspect every hopper ID, inventory, filter, component,
  enchantment and custom state, then save/restart and repeat. Keep the original
  backup untouched. Never downgrade a world already saved in 1.21.11.
